# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the app

The app is a single-file HTML application (`index.html`). Serve it with `npm start` (runs `http-server . -p 3000 -o`). There is no build step.

To run Playwright tests: `npm test`. Tests expect the dev server to be running on port 3000 (see `playwright.config.js`).

## Architecture

Everything lives in `index.html` — CSS, HTML markup, and JavaScript are all inline in one file.

### State model

A single `state` object is the source of truth:

```js
state = {
  basics:      { name, grade, semStart, semEnd },
  subjects:    [ { id, name, teacher, color } ],
  schedule:    { mon: [], tue: [], wed: [], thu: [], fri: [], sat: [] },  // each entry: { id, time, subjectId, room }
  homework:    [ { id, title, subjectId, dueDate, priority, description, completed, createdAt } ],
  topics:      { "YYYY-MM": [ { id, subjectId, text } ] },
  reviews:     { "YYYY-MM-DD": [ { id, text, subjectId, completed } ] },
  hwFilter:    'all' | 'open' | 'done' | 'overdue' | 'week',
  selectedDate: null | 'YYYY-MM-DD',  // null = real today; set by ← Prev / Next → buttons
  weekOffset:  0
}
```

### Storage buckets

State is persisted through `window.storage` (an async platform API — not `localStorage`). Each domain maps to its own key so a homework save never re-serialises unrelated data:

| Bucket key | State field |
|---|---|
| `planner-basics` | `state.basics` |
| `planner-subjects` | `state.subjects` |
| `planner-schedule` | `state.schedule` |
| `planner-homework` | `state.homework` |
| `planner-topics` | `state.topics` |
| `planner-reviews` | `state.reviews` |

Call `saveBucket('homework')` (or whichever field changed) — never write all buckets unless every field is dirty. On first load, `migrateLegacy()` moves data from the old single-blob `planner-data` key into the separate buckets.

### Rendering pattern

All rendering is DOM-based `innerHTML`. The flow is:

1. Any mutation → call `saveBucket(name)` for each dirty field
2. Then call `renderAll()`, which delegates to individual `render*()` functions:  
   `renderBasics`, `renderSubjects`, `renderSchedule`, `renderHwList`, `renderToday`, `renderWeek`, `renderMonthDropdown`, `renderMonthList`, `renderStorageStatus`

Each `render*` function reads from `state` and writes directly to specific DOM elements by ID.

### Today panel navigation

`state.selectedDate` drives which day the Today panel shows. It is `null` when showing the real current day. Navigation is entirely button-based — there is no `<input type="date">`:

- `shiftDay(±1)` — moves one day forward or back and sets `state.selectedDate`
- `jumpToToday()` — resets `state.selectedDate` to `null`
- `#dayNavLabel` — a `<span>` that `renderToday()` populates with the human-readable date (e.g. "Sat, May 23, 2026")

### Key conventions

- **Dates** are stored and compared as ISO strings (`YYYY-MM-DD`). When constructing `Date` objects from stored strings, always append `'T00:00:00'` to avoid UTC-offset bugs.
- **Times** are stored as 24-hour `HH:MM` strings; `fmtTime()` converts to 12-hour for display.
- **IDs** are generated by `uid()` (`Math.random().toString(36).slice(2,10)`).
- **Subject colors** are assigned cyclically from `SUBJECT_COLORS` (CSS vars `--c1` through `--c8`).
- **User content in innerHTML** must go through `escapeHtml()` to prevent XSS.
- `window.storage` is async; `loadState()` uses `Promise.allSettled` to load all buckets in parallel without failing on missing keys.
- `window.__plannerReady = true` is set at the end of the init IIFE — Playwright tests wait for this before running.
